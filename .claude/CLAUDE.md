# blog-app 项目规范

## 学习笔记规则

- 每 20 轮对话更新一次 `学习笔记.md`。
- 学习笔记按主题分类（环境与工具、前端、后端、部署、项目技术栈等），新增内容插入对应主题下，不能无序追加。
- 每个主题的结构：**前面是知识点记录**（简明扼要、有重点，方便复习速查），**后面是反思/疑问**（学习过程中产生的真正有价值的思考）。
- 单纯问知识点的内容不算反思，应该整理后插入前面的知识点部分。

## 沟通方式

- **默认教学指导模式**：只指导、引导，不直接操作代码。
- **一步一步来**：每次只教一步，留下思考和按自己想法调整的时间和空间。
- **解释原则**：每处增加或修改的内容，必须解释"在做什么、为什么要这么做"，适当时候介绍语法规则。
- 我使用 Cursor 和 VSCode 编辑代码（主要是 Cursor）。

## 项目信息

- xlab 教学内训项目 — **"从 0 到 1 的博客网站"**。
- 技术栈：Node.js / Express / EJS / SQLite / bcryptjs。
- mentor 通过 GitHub 仓库验收，最终验收时需提供 GitHub 仓库 + 公网访问地址。

### 验收节点（方案 2）

| DDL | 要求 |
|-----|------|
| 6.7 | 完成基本设计和项目框架，向 mentor 提供 GitHub 仓库，允许验收 |
| 6.14 | 完成基础功能（至少用户 + 博客两大模块），提供功能截图，允许验收 |
| 6.21 | 完成部署 + 进阶功能（1-2 个），提供可访问成品 |

### 最终验收标准

- 至少实现用户、博客、评论、点赞四大基础模块 + 1-2 个进阶功能。
- 进阶功能方向：agent、游戏、区块链等自己感兴趣的领域。
- 评判侧重：创意 > 数量（避免同原理功能堆砌），理解程度 > 功能本身。
- 验收方式：线上组会或 1v1，侧重感受和收获，少量基础知识提问。
