# 四、部署：让外界能访问

> 学习笔记分册 · 返回 [总目录](../学习笔记.md)

## 关键概念

```
localhost → 本机地址，只有自己的电脑能访问（开发阶段用）
部署     → 把代码放到公网服务器，绑定 IP/域名（最后一步）
```

## 静态部署 vs 服务器部署

| | GitHub Pages | 阿里云/自有服务器 |
|---|---|---|
| 托管什么 | 静态文件（HTML/CSS/JS） | 完整的后端程序 + 数据库 |
| 能做什么 | 展示固定内容、借助 giscus 评论 | 注册登录、评论、点赞、搜索 |
| 成本 | 免费 | 学生试用或自购 |
| 典型工具 | Hugo、Zensical、Hexo | Express、Gin、Django |

## 本项目的部署

- 部署到**阿里云 ECS**（云服务器），公网地址 http://118.178.231.82:3000/
- 服务器上跑 `node app.js` 常驻，监听 3000 端口对外服务
- 因为项目是 Express + SQLite 的**动态服务**（要注册登录、写数据库），只能走服务器部署，不能用 GitHub Pages 这类静态托管
- 进阶：生产环境用 `pm2` 等进程管理工具，能掉线自动重启、开机自启，比裸 `node app.js` 稳

## 反思

> **教学文档提了 Zensical，为什么不照着做？** — 文档有两部分："静态部署与个人博客框架"是铺垫知识（了解部署概念），"从 0 到 1 的博客网站"才是验收项目。验收要求的用户注册登录、评论、点赞，静态博客做不到。不是 Zensical 不好，是验收目标决定技术选型。

> **为什么 AI 一开始推荐 Hugo？** — AI 拿到"个人博客"这个需求，默认给出的就是最流行、最省力的路线（Hugo + GitHub Pages）。但加了验收约束（用户系统、评论、点赞）之后，这个路线就不通了。需求决定架构，不是工具决定架构。

> **`*.github.io` 仓库只能放静态文件。** — GitHub 自动把同名仓库发布到 GitHub Pages，但只认 HTML/CSS/JS，不跑后端。Express + SQLite 是动态服务，放到 `*.github.io` 仓库跑不了。代码仓库和部署地址是两回事：代码放 `blog-app`，部署走阿里云（6.21）。`Lye3377.github.io` 留着以后放个人主页用。
