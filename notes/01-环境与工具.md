# 一、环境与工具

> 学习笔记分册 · 返回 [总目录](../学习笔记.md)

## 知识速查

```
终端：一次一条命令，多条用 && 连接
PATH：终端从哪里找可执行程序。安装成功 ≠ 在 PATH 里。
验证：装完任何工具，第一时间跑 version 确认可用。
```

## 包管理器层级

| | 层级 | 管什么 | 类比 |
|---|---|---|---|
| Homebrew | 系统全局 | 独立程序（git, hugo, node） | 给电脑装 App |
| npm / pip / gem | 项目级 | 某个语言的代码依赖 | 给项目装零件 |

- `npm install` 的核心意义：代码不搬运，只记录依赖清单（package.json）。别人拿到项目跑 `npm install` 即恢复。
- `--save-dev`：仅在开发时需要（nodemon），部署不需要。

## 配置文件格式

- TOML：`[section]` + `key = "value"`，不依赖缩进，新手友好。
- YAML：靠缩进表示层级，更简洁但易出错。
- 作用完全相同，选哪个看项目习惯。

## Git 工作流

```
git init                    → 初始化本地仓库（项目根目录跑一次即可）
git add -A                  → 标记所有文件进暂存区
git commit -m "xxx"         → 记录快照
git remote add origin <url> → 关联 GitHub 远程仓库（只需一次）
git push -u origin main     → 推上去，-u 是设默认远程分支（只需一次）
                                                                     之后直接 git push
```

- Git ≠ GitHub。Git 是版本控制工具，GitHub 是托管 Git 仓库的网站。
- GitHub 2021 年起禁用密码登录，用 GitHub CLI（`gh auth login`）替代。
- `.gitignore`：告诉 git 忽略哪些文件（node_modules/、.db、.DS_Store）
- `package-lock.json` 要进仓库（锁定版本号），`node_modules/` 不进（靠 npm install 恢复）
- GitHub 仓库名随便取，只要不是 `*.github.io`（那个是静态托管专用，见 [四、部署](04-部署.md)）

## 反思

> **安装后为什么必须验证？** — 不是走形式。终端可能没刷新 PATH，安装成功和命令可用是两件事。以后排查问题的第一步永远是确认基础环境。

> **npm 和 brew 不是"脚本 vs 应用"的区别** — 有人会这么概括，但真实分界线是层级：系统全局 vs 项目局部。理解了层级，pip、gem 这些概念自然就通了。
