# 二、前端：浏览器里运行的

> 学习笔记分册 · 返回 [总目录](../学习笔记.md)

## 知识树

```
前端三件套
├── HTML ─ 结构："页面上有什么"（骨架）
├── CSS  ─ 样式："长什么样子"（装修）
└── JS   ─ 行为："能干什么"（开关、交互）

页面渲染方式
├── 纯 HTML ─ 死的，写什么显示什么
└── 模板引擎（EJS）─ 活的，HTML 里嵌入 JS 逻辑
                     同一个模板 + 不同数据 = 自动生成不同页面
                     最终发给浏览器的还是 HTML
```

## views/ vs public/

| | views/ | public/ |
|---|---|---|
| 放的什么 | EJS 模板 | CSS、前端 JS、图片 |
| 谁处理 | 服务器先填数据再返回 | 直接发给浏览器 |
| 能直接访问吗 | 不能 | 能（`/css/style.css`） |

- `partials/`：可复用的页面片段（导航栏、页脚）。多页面共享的部分写一次，用 `<%- include('partials/xxx') %>` 引用。完整页面不放这里。

## 数据可视化：Chart.js

阅读统计仪表盘用 Chart.js（CDN 引入，不用装 npm 包）画柱状图。

- 引入：`<script src="https://cdn.jsdelivr.net/npm/chart.js"></script>`
- 后端数据传前端：`var data = <%- JSON.stringify(stats) %>;`（`<%-` 不转义，输出的是合法 JS 数组/对象）
- 画图：`new Chart(canvasEl, { type: 'bar', data: {...}, options: {...} })`
- 常用配置：`scales.y.beginAtZero`（Y 轴从 0 开始）、`ticks.precision: 0`（刻度取整）

**踩坑：EJS 会扫描整个模板找 `<% %>`，连 `<script>` 里的 JS 注释也不放过。** 如果注释里出现了 `<%-` 这种字符，EJS 会当成没闭合的标签，直接报错「Could not find matching close tag」。所以模板里任何位置（包括注释）都别写裸的 `<%`。

## 反思

> **为什么是 EJS 而不是 HTML？** — 因为博客文章是动态的，不可能每写一篇就手写一个 HTML 文件。模板引擎让你用一套结构 + 变化的数据库内容，自动生成所有页面。这是"动态网站"最直观的含义。

> **views 和 public 的本质区别不在文件类型** — 在于"是否需要服务器加工"。这个区分是 Web 开发的基础共识：静态资源走 CDN/直接返回，动态内容走模板渲染。
